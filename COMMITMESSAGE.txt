fix(viz): the SEPARATOR line must not use the separator it declares

iTOL rejected every dataset with "separator needed". The files were written as
`SEPARATOR<tab>TAB`, which looks consistent and is wrong: iTOL has to read that
line before it knows what the separator is, so the keyword and its value are
always divided by a single space. That is also why `SEPARATOR SPACE` is a legal
thing to write. Confirmed against iTOL's own dataset_binary_template.txt rather
than from memory.

The failure mode is the worst kind available here. The declaration is the first
thing parsed, so nothing else in the file is ever reached, and the error names a
missing separator in a file that is otherwise entirely separator-delimited --
which sends the reader looking at the 357 data rows.

All five writers had it. The test sweeps every one of them rather than checking
a single dataset, since this is a constant that any new writer would copy.

306 tests passing.
