feat(phylo,viz): relative divergence rates, and a display rank chosen by budget

Two modules, both answering questions the package could previously only be
asked informally.

phylo/rates.py -- relative divergence rate between clades.

Measured crown-to-tip, not root-to-tip, and that is the whole design. From the
root every path carries its clade's stem branch, which is one number shared by
every taxon in that clade; it would enter every paired difference as a constant
and read as a rate difference it is not. Measured from each clade's own crown
the comparison is between within-clade path lengths for the same species, which
is what a relative-rate statement is about. Stem lengths are reported
separately, since the branch over which a paralogue diverged after the
duplication is a quantity of interest rather than a nuisance. The regression
test changes the stems from 0.5/0.3 to 2.0/0.01 and asserts that nothing about
the rates moves.

The comparison is paired within taxon, for the reason the project already
pairs the APR load: tips inside a clade share branches, so a clade mean is not
an average of independent observations and a difference between two clade means
has no standard error that treats it as one. Where one taxon carries a sequence
in two clades the species history below the duplication is shared, so the
paired difference isolates the paralogue. Clade means are still reported,
labelled descriptive, with the reason no test compares them directly.

Tests are sign-flip permutations on the paired differences rather than Wilcoxon,
and no dependency was added to get the latter: ranking the differences would
discard their magnitude, and the permutation floor is already a convention here.
MIN_PAIRS = 10 is about attainable resolution and not about normality -- a
sign-flip test over n pairs has 2**n assignments, so at four taxa the smallest
reachable p is 2/16 however large the effect. A test pins exactly that: clade B
at twice clade A's rate, every paired difference identical, p still 0.125.

On dating, the module's first draft said absolute ages were unavailable because
a gene family has no fossils. That is wrong where the paralogues are ohnologs:
the duplication node IS the whole-genome duplication, which was dated without
reference to the family, so it is a real external calibration. DATING_CAVEATS
now says so, and says what still bites -- two WGD rounds leave two duplication
nodes at different depths, a calibration on the wrong one is wrong by the
interval between the rounds, and a rate over substitutions per site is a rate
over the sites that aligned.

viz/represent.py -- one representative per taxonomic level, at whichever rank
fits a row budget.

The rank is found from the data rather than declared, because on an orthologue
set the obvious choice is the wrong one. A genus contributes about one sequence
per paralogue, so one representative per genus cuts the pooled set by two
thirds and a single paralogue group by under a fifth -- and a per-group figure
only ever sees the second number. Measured on the FXR1 family: genus takes FXR1
from 116 rows to 96, still twice a readable panel, while order takes it to 42.
choose_rank walks finest to coarsest and stops at the first rank inside the
budget, so a scope gets the most resolution it can afford; a test asserts that
the same metadata yields genus for one group and family for the pooled set.

Three refusals, each of them a way the function could otherwise mislead
quietly. Nothing is dropped to meet an impossible budget, because choosing
which clades a figure omits is not a decision a row count can make. A rank with
more levels than the finer rank above it does not nest -- one genus filed under
two families -- and is reported instead of used. Sequences with no value at the
rank are pooled rather than dropped, since dropping them removes whichever
clade the taxonomy is worst for, which on this family is the invertebrates.

The representative is chosen by alignment completeness and never by anything
the figure displays; picking by APR content or by support would make the panel
select on its own variable and look cleaner than the data in a way the reader
cannot see. format_selection_report prints the column used as a caption line so
the figure carries it, and reports how many levels were decided by the
tie-break, which is the honest measure of how arbitrary the panel is.

dating_command now takes the result of dating_inputs() as a required argument
and refuses to emit a command when it does not pass. The first version took
two paths and trusted them, and the command it produced paired the
372-sequence alignment with the 357-tip tree -- a mismatch IQ-TREE reports
only after reading and analysing both files, several hundred lines into a run.
The cause is structural rather than careless: the tree is inferred from a copy
of the alignment filtered at MIN_TIP_OCCUPANCY, and that filtered copy is
never written out, so the two files a pipeline naturally hands you are exactly
the two that disagree. dating_inputs names the difference in both directions
and says which cause each one implies; matched_alignment builds the subset the
tree carries, leaving columns alone, since trimming all-gap columns would
renumber every block coordinate the project reports against.

dating_command also passes --keep-ident by default, and on this project that
is a decision about the data and not a convenience. IQ-TREE otherwise reduces
the alignment to unique sequences -- 333 of 357 here -- and then rejects a
fixed tree that still carries 357 tips, which is a second mismatch with the
same symptom and a different cause. Keeping them is what the analysis needs
anyway: of the 33 groups of identical tips on this family, one carries
different APR traits between its members, so de-duplicating deletes an
observation rather than a redundant row, and pruning the tree to the reduced
set would do the same thing less visibly.

That second case also marks the limit of dating_inputs, which the docstring
now states: it compares the two FILES, and the reduction happens inside the
tool, so two files that agree exactly can still fail and nothing readable from
them predicts it. The tree-only branch of the message used to assert the files
came from different runs; it now names de-duplication as the other cause and
points at the flag, because the wrong half of that message is the half that
fires in practice.
