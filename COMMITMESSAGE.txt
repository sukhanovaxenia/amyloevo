fix(phylo): the lambda column printed a dash in every row

`format_phylo_report` read each value off `DataFrame.itertuples`, which renames
any column that is not a valid Python identifier. `lambda` is a keyword, so
`row.lambda` can never exist, the `getattr` fallback returned nan, and the whole
Pagel's-lambda column rendered as `--` for every block. Nothing errored: the
report was well formed and silently missing one of the two statistics the step
exists to produce. Found by running the step against a stand-in for Rscript and
looking at the output, not by reading the code.

Two changes, because either alone would leave the trap in place:

* the report reads rows as dicts, so no column name can be mangled on the way
  in, and it falls back to the bare name as well;
* the R script now writes `pagel_lambda`, with a comment saying why it is not
  called `lambda`.

Also corrects the paired-contrast count in the R script's comment on why the
clade is not a regression predictor: the paired within-taxon contrast runs over
55 taxa, not 82. 87 of 104 taxa carry all three paralogues, the completeness
filter leaves 55, and the 82 in DESIGN.md section 4 is a third quantity --
sequences per taxon over all 372, invertebrates included. Three counts, one of
which is the sample size of the test offered as the honest alternative to
phyloglm, so it is worth having right.

250 tests passing. The new ones pin that a lambda value given to the report
appears in it, under either column name.
